# Архитектура Research Assistant

[Вернуться к проекту](../README.md)

Состояние: проектирование, 02.10.2026. Перечисленные сервисы и интерфейсы ещё предстоит реализовать. Структура уточняется по результатам первых запусков; схема поиска **BM25 + bi-encoder + cross-encoder** составляет основу модельной части.

## 1. Граница обязательной версии

Вход — основная научная статья и доступные цитируемые работы. Выход — ответ с проверяемыми фрагментами и страницами либо сообщение о недостатке материала. Первая версия работает с цифровыми англоязычными PDF, одним переходом по библиографии и ограниченным числом документов в пространстве.

Граф нужен для связи документов и происхождения доказательств. Для него достаточно таблиц статей и рёбер. Графовая нейросеть, многошаговый агент, OCR сканов и визуальный retriever не являются предпосылками работающего продукта.

## 2. Развитие реализации

| Этап | Устройство | Зачем это нужно |
|---|---|---|
| Подготовка данных | Переиспользуемые Python-скрипты, CSV/JSONL, локальные PDF | Отладить сбор источников и разметку на небольшом корпусе |
| Baseline | Парсер текста, фиксированное разбиение, BM25 и оценка | Получить первую измеримую точку отсчёта |
| Сервис | FastAPI, worker, PostgreSQL, файловое хранилище, простой интерфейс | Дать пользователю полный сценарий загрузки и поиска |
| DL-поиск | Bi-encoder, векторный индекс, объединение выдач, cross-encoder | Проверить улучшение retrieval при тех же данных |
| Ответ и выпуск | Сменяемый LLM, проверка ссылок, права доступа, наблюдаемость | Сформулировать ответ и довести сервис до демонстрации и эксплуатации |

Не нужно сразу создавать все будущие каталоги или запускать несколько микросервисов. Модульный Python-проект позволяет использовать один код из CLI, HTTP API и worker.

## 3. Компоненты и контракты

| Модуль | Вход | Выход и ответственность |
|---|---|---|
| `ingestion` | PDF, arXiv ID, пользовательские метаданные | Проверенный файл, хеш, извлечённый текст и библиография |
| `references` | Одна запись библиографии | Кандидаты публикаций, проверенное сопоставление или явный статус неуспеха |
| `corpus` | Документы, страницы, связи | Версия корпуса и фрагменты с устойчивыми адресами |
| `retrieval` | Вопрос, пространство, версия индекса, лимит | Список кандидатов BM25, bi-encoder или гибрида |
| `reranking` | Вопрос и ограниченный пул кандидатов | Те же кандидаты с оценками cross-encoder и новым порядком |
| `answering` | Вопрос и пакет доказательств | Текст ответа, evidence IDs, ограничения, сведения о генераторе |
| `evaluation` | Фиксированные вопросы, разметка и предсказания | Метрики, результаты по каждому вопросу, отчёт об ошибках |
| `api` и `jobs` | Запросы пользователя и фоновые задания | Управление сценарием, прогресс, повтор, проверка доступа |
| `frontend` | Состояние API и разрешённые PDF | Загрузка, граф публикаций, вопрос, ответ и просмотр доказательств |

Будущие интерфейсы `DocumentParser`, `ReferenceResolver`, `Retriever`, `Reranker` и `Generator` описываются через обычные типизированные структуры. Выбор модели, параметры разбиения и лимиты находятся в конфигурации. Предсказания содержат версию этой конфигурации.

## 4. Приём документов и источников

1. Проверить тип, размер и читаемость PDF; вычислить SHA-256. Сохранить версию статьи и происхождение файла.
2. Извлечь библиографию. Для первого прототипа рассматривается GROBID: `processReferences` для списка литературы, `processFulltextDocument` для структурированного текста и связей. Исходные строки библиографии сохраняются вместе с разобранными полями.
3. Пройти по **каждой** записи. Точное совпадение DOI/arXiv ID проверяется первым; при поиске по названию сверяются авторы и год. Неоднозначная запись остаётся неоднозначной до проверки.
4. Получить метаданные из подходящего каталога, затем найти доступную полную версию. Crossref помогает с метаданными; arXiv — с версиями препринтов; Unpaywall может указать открытое размещение публикации по DOI. Ответ API не гарантирует существование доступного PDF.
5. Скачать разрешённый файл, проверить содержимое и связать с публикацией. HTML-страница, вернувшаяся с кодом 200, не считается PDF. Сетевую ошибку не приравнивать к отсутствию открытой версии.
6. Сохранить результат и журнал попыток. Повторный запуск использует уже полученные файлы и проверенные сопоставления. Ручное исправление сохраняет основание решения.

Реализация опирается на [официальную документацию источников](references.md). Для небольшого пилота допустимо вручную исправить распознанную библиографию, если исходный результат и исправления сохранены. Качество парсера оценивается отдельно от качества поиска публикаций.

## 5. Сущности и происхождение данных

| Сущность | Основные сведения |
|---|---|
| `Workspace` | Владелец, основная статья, список доступных документов, активная версия индекса |
| `Paper` и `DocumentVersion` | Каноническая публикация, семейство версий, DOI/arXiv ID, версия PDF, хеш, источник и лицензия |
| `Reference` | Основная статья, номер записи, исходная строка, кандидаты, итог сопоставления |
| `CitationEdge` | Статья-источник ссылки и цитируемая статья; контекст цитирования, если извлечён |
| `PageText` | PDF, страница, текст и версия извлечения |
| `Chunk` | Документ, интервалы страниц/символов, текст, правило разбиения и индексная версия |
| `Evidence` | Проверенный фрагмент и его адрес в конкретной версии PDF; хранится независимо от будущих chunks |
| `Job` | Состояние обработки, попытки, ошибка, время, возможность возобновления |
| `Answer` | Вопрос, индексная версия, доказательства, текст, модель и параметры генерации |
| `Run` | Коммит кода, снимок корпуса, параметры, оборудование, предсказания и метрики |

Номер страницы PDF начинается с 1 и отличается от номера, напечатанного в журнале. Координаты области хранятся, если парсер надёжно их выдаёт; в первом варианте достаточно проверенного текста и номера страницы. Нельзя обещать точное выделение области без проверки координат.

Разметка второго чекпойнта сохраняет исходные доказательства, а не будущие chunk IDs. После выбора разбиения отдельная таблица связывает доказательства с поисковыми фрагментами. Смена парсера или границ фрагмента требует новой версии этой таблицы.

Для пилота действуют [CSV/JSONL-схемы](../data/checkpoint02/SCHEMA.md). После появления сервиса те же идентификаторы и связи переносятся в базу. PDF остаются в файловом или S3-совместимом хранилище. Публичный доступ к статье не означает разрешения распространять её копию: для публикации набора проверяется лицензия конкретной версии.

## 6. Поиск и ранжирование

Поиск ограничен документами текущего рабочего пространства и его зафиксированной версией. Эталонные ответы, тексты вопросов и служебная разметка в индекс не включаются.

**BM25.** Строится по фрагментам исходного текста. Токенизация, нормализация, параметры `k1` и `b` сохраняются. Выдача BM25 служит самостоятельным baseline.

**Bi-encoder.** Векторы документов вычисляются заранее. Вектор вопроса получается той же согласованной моделью; сравнение использует метрику и нормализацию из её конфигурации. На небольшом пилоте допустим точный поиск по векторам. При переходе к приближённому индексу отдельно проверяются потери retrieval.

**Общий пул.** Оба метода ищут параллельно по одному набору chunks. Начальный ориентир — `top_k_bm25 = 50`, `top_k_dense = 50`; значения ограничиваются фактическим числом фрагментов. Объединение выполняется по `chunk_id`, а позиции соединяются через Reciprocal Rank Fusion:

`rrf(chunk) = sum(1 / (rrf_constant + rank_method(chunk)))`

Ранги начинаются с 1; отсутствующий в выдаче метода фрагмент не даёт слагаемого. `rrf_constant = 60` — стартовая настройка проекта для проверки, не измеренный оптимум. Равные оценки разрешаются устойчивым порядком идентификаторов. Перекрывающиеся, но разные фрагменты сначала сохраняются: преждевременное удаление может потерять доказательство.

**Cross-encoder.** Оценивает каждую пару «вопрос — кандидат», затем упорядочивает общий пул. До и после этого шага сохраняются IDs и позиции. Стартовый лимит контекста — до 10 верхних кандидатов, дополнительно ограниченных числом токенов. Настройки подбираются на данных разработки. Если релевантного материала нет в пуле, ранжировщик не исправит этот пропуск.

Сравниваются четыре режима: `bm25`, `bi_encoder`, `hybrid`, `hybrid_cross_encoder`. Размер исходного пула у двух гибридных режимов одинаков. Качество, время и память измеряются отдельно; смена нейронной модели не считается улучшением, пока это не показал опыт.

## 7. Генерация и ссылки

Генератор получает вопрос и пронумерованные фрагменты. Возвращает утверждения с evidence IDs; приложение само формирует переходы к PDF. В инструкции модели текст документа отделяется от команд: содержание статьи не может запускать инструменты или менять права доступа.

Проверяются три разных свойства:

- **Целостность:** IDs существуют и принадлежали переданному контексту.
- **Доступ:** пользователь имеет право открыть соответствующий документ.
- **Смысловая поддержка:** фрагмент действительно подтверждает утверждение. Сначала она проверяется человеком на выборке; автоматический verifier вводится только с собственной оценкой ошибок.

При недостатке подтверждений система показывает найденный материал и ограничение ответа. Оценка cross-encoder не интерпретируется как вероятность истинности. Без работающего генератора пользователь всё равно получает retrieval и страницы источников.

OpenRouter рассматривается как первый внешний адаптер. Для каждой серии сохраняются идентификатор модели, фактический провайдер, промпт, параметры и ответы. Бесплатная модель не обязательно имеет открытые веса, а доступ через API не равен локальной воспроизводимости. Автоматическое переключение на другой генератор внутри сравнения отключается. Оплаченный fallback и аренда GPU заранее не предполагаются. Квоты проверяются перед работой по [документации OpenRouter](https://openrouter.ai/docs/api/reference/limits).

## 8. API, задачи и интерфейс

Это проект маршрутов, не описание уже работающего сервера.

| Маршрут | Назначение |
|---|---|
| `POST /workspaces` | Создать пространство |
| `POST /workspaces/{id}/documents` | Принять PDF или ссылку и вернуть ID фоновой задачи |
| `GET /workspaces/{id}/references` | Показать библиографию, совпадения и доступность источников |
| `PATCH /workspaces/{id}/references/{reference_id}` | Подтвердить или исправить сопоставление |
| `GET /jobs/{id}` | Получить этап обработки, статус и причину ошибки |
| `POST /workspaces/{id}/search` | Получить фрагменты без генерации |
| `POST /workspaces/{id}/questions` | Создать ответ по заданной версии индекса |
| `GET /answers/{id}` | Прочитать ответ и доказательства |
| `GET /workspaces/{id}/graph` | Получить статьи, статусы и связи |
| `GET /documents/{id}/file` | Открыть разрешённую версию PDF |
| `DELETE /workspaces/{id}` | Удалить пространство и связанные производные данные |

FastAPI обслуживает HTTP, worker обрабатывает PDF и индексирует. Предварительный выбор очереди — Celery с Redis; совместимость проверяется при реализации сервиса. Состояния задач: `queued`, `running`, `partial`, `completed`, `failed`, `cancelled`. Повторы ограничены; ключ обработки включает хеш файла и конфигурацию. Сборка новой версии индекса завершается переключением активной версии только после успеха.

Интерфейс на React/TypeScript включает библиотеку, граф, вопрос с ответом и PDF.js. Клик по доказательству открывает страницу; граф показывает наличие полного текста. Отдельные экраны обучения моделей пользователю продукта не нужны.

Исходные требования сохраняются. Совместимость библиотек ещё не проверена; изменения обязательного стека не объявляются согласованными.

| Требование курса | План применения или вопрос для согласования |
|---|---|
| Python 3.10.4 | Воспроизводимое учебное окружение; допустимую версию для будущего публичного сервера уточнить до развёртывания |
| pip, conda | pip для установки закреплённых зависимостей; необходимость отдельной conda-среды уточнить |
| pyenv, poetry, pyenv-virtualenv | pyenv задаёт Python, pyenv-virtualenv — среду, poetry — описание и фиксацию зависимостей без второго вложенного окружения |
| Git, GitLab | GitHub выбран для проекта; обязательность зеркала в GitLab уточнить |
| DVC, Google Drive | Версии разрешённых данных и workflow; удалённое хранилище подключить после предоставления доступа, без ключей в Git |
| Cookiecutter | При создании Python-пакета выбрать шаблон и сохранить его ревизию; не выдавать нынешние Markdown-заготовки за созданный пакет |
| flake8, black | Форматирование и lint с появлением исполняемого Python-кода |

| MLflow | Экспериментальные параметры, метрики и артефакты с этапа baseline; эксплуатационные логи ведутся отдельно |
| pandas, NumPy, sklearn, PyTorch, CatBoost | Анализ данных и DL; необходимость CatBoost в DL-треке уточнить, не добавлять модель без задачи для сравнения |
| pyautogui | Для серверного PDF-парсинга предложены GROBID и извлечение текста по страницам; замену исходного parsing-стека согласовать |
| pytest | Проверки сопоставлений, загрузки, данных, метрик и API по мере реализации |

Неподтверждённые трактовки общего списка не препятствуют оформлению организационного чекпойнта, но должны быть решены до соответствующей реализации.

## 10. Надёжность и приёмка

- Ограничить размеры PDF, время разбора и число одновременно обрабатываемых документов. Для публичного загрузчика проверять адреса и перенаправления, исключая обращения к внутренней сети.
- Учитывать `Retry-After`, временные сбои и квоты внешних источников. Сохранять кэш и причины неуспеха без секретов.
- Фильтровать все запросы по владельцу и пространству, включая прямые URL файлов, граф и векторный поиск. Удаление включает производные индексы и кэш.
- Отправку пользовательских документов внешнему генератору делать явным режимом с указанием провайдера. Демо строить на открытых материалах.
- Собирать длительность обработки, размер очереди, память, p50/p95 поиска и ошибки API. Профиль нагрузки и машину указывать рядом с результатами.
- Проверять восстановление базы и файлов, остановку worker, повторную загрузку и недоступность LLM. До этих проверок сервис не называется отказоустойчивым или высоконагруженным.

Итоговая демонстрация включает основную статью, несколько источников, вопрос с доказательством, недоступный источник и восстановление после сбоя. Исследовательские сценарии описаны отдельно в [протоколе](research-protocol.md).
