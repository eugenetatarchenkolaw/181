# Чекпойнт 2: сбор источников и контрольные вопросы

[Проект](../../README.md) · [План](../roadmap.md) · [Протокол оценки](../research-protocol.md)

**Ориентировочный срок — конец октября 2026 года; точный дедлайн ожидается.** Сейчас подготовлены формы данных, правила работы и шаблон отчёта. PDF не собраны, вопросы не размечены, скрипт загрузки ещё не реализован. Пустые формы не являются результатом выполнения чекпойнта.

## 1. Результат этапа

Нужно показать два связанных результата:

1. Переиспользуемый Python-инструмент получает библиографию основной статьи, проходит по всем записям, собирает сведения о публикациях и пытается найти и скачать доступные полные тексты.
2. На выбранных цитируемых работах подготовлен фиксированный набор вопросов, эталонных ответов и доказательных фрагментов. Он будет одинаковым для последующих сравнений поиска.

Исходный объём — **минимум пять основных статей**. Формулировка «по пять вопросов из дочерних статей» требует уточнения: по пять на основную статью или на каждую выбранную цитируемую работу. Для подготовки принят более содержательный рабочий ориентир: по два доступных источника у каждой основной статьи, по пять вопросов на источник — **50 записей**. Это решение проекта, а не приписанное куратору точное требование. Если источники повторяются, считаются также уникальные вопросы и статьи; одинаковый вопрос не размножается ради объёма.

## 3. Выбрать основные статьи

Рабочая рекомендация — одна узкая тема на пересечении научного поиска и NLP, например retrieval для вопросов по научным документам. Конкретный список выбирает автор после чтения названий, аннотаций и библиографии.

Для каждой основной статьи нужно проверить:

- цифровой PDF читается и содержит список литературы;
- это самостоятельная работа, а не другая версия уже выбранной публикации;
- среди её источников есть доступные работы, в которых можно проверить ответы;
- тема понятна настолько, чтобы заметить неверно сформулированный вопрос;
- записаны причина выбора, источник файла и версия.

Отбор по доступности источников создаёт смещение выборки. Для пилота оно допустимо, если описано в отчёте; выводы о всей научной литературе на таком наборе не делаются.

## 4. Собрать библиографию и полные тексты

На первой основной статье пройти весь путь вручную и программно, затем расширить на остальные:

1. Получить основной PDF, вычислить SHA-256, извлечь список литературы с исходными строками.
2. Сверить число и содержание записей с PDF. Ошибки извлечения исправить с сохранением исходного результата.
3. Для **каждой** записи запустить определение DOI/arXiv ID или поиск по метаданным. Сохранить кандидатов и основание выбранного совпадения.
4. Для подтверждённого совпадения проверить открытое размещение и попробовать скачать PDF. Сохранить адрес, хеш, дату, доступную информацию о лицензии и версию.
5. Зафиксировать недоступность, неоднозначность и технические ошибки отдельно. Если источник получен вручную, отметить это — ручной файл не считается успешной автоматической загрузкой.
6. Повторить запуск и проверить, что обработка возобновляется без дублирования.

Успешность этапа не означает скачивание 100% библиографии. Проверяемый результат — полный учёт записей, работающий способ получения доступной части и объяснимые причины неуспеха. Для нераспознанной ссылки тоже нужна запись в журнале. Точные PDF и производные тексты хранятся вне Git в `data/raw/` и `data/processed/`; допустимые данные впоследствии версионируются через DVC.

## 5. Подготовить вопросы

Сохраняется цепочка **основная статья → запись её библиографии → цитируемая работа → доказательство → вопрос и ответ**. Ответ берётся из цитируемой работы, а не из предположения о том, что в ней должно быть.

- Выбрать источники для разметки и отметить этот выбор в отчёте. Он не сокращает список ссылок, обрабатываемых загрузчиком.
- В выбранной работе сначала найти содержательный фрагмент и проверить его по странице PDF.
- Написать вопрос и короткий эталонный ответ вручную либо использовать [подготовленный промпт](../../prompts/question_from_evidence.md).
- Проверить факты, числа, условия и достаточность цитаты. Если доказательство не позволяет ответить, отклонить вопрос.
- Убрать дубли и вопросы, которые различаются только поверхностной переформулировкой. Желательно распределить вопросы по нескольким частям работы.
- Внести идентификаторы, способ подготовки и сведения о ручной проверке. В итоговую часть входят только записи `approved`.

В основной статье могут встречаться краткие пересказы результата источника. Это нужно отметить при анализе, но не заменять ими разметку цитируемого полного текста. Позже контроль «только основная статья» поможет понять, насколько вопросы действительно требуют её источников.

## 6. Проанализировать и зафиксировать

В отчёте должны быть числа по каждой основной статье и по корпусу в целом:

- записи библиографии: в PDF, извлечены автоматически, добавлены или исправлены вручную;
- подтверждённые, неоднозначные и не найденные совпадения;
- доступные PDF: скачаны автоматически, добавлены вручную, не получены;
- уникальные публикации, общие источники, версии и дубликаты;
- страницы, качество извлечения текста и причины исключения из поиска;
- черновые, принятые и отклонённые вопросы; уникальные доказательства и типы вопросов.

Доля автоматической загрузки считается относительно **всех** учтённых записей библиографии и дополнительно относительно подтверждённых совпадений. Число файлов показывается отдельно: один PDF может закрывать несколько записей. Недоступные источники не исчезают из знаменателя.

После исправлений создать `manifest.json` на основе шаблона: фактические количества, дата, хеши файлов разметки и манифеста корпуса, идентификатор версии и проверенный снимок кода. На следующих этапах вопросы и ответы не подгоняются под метод. Если выявлена ошибка, выпускается новая версия и сравнения повторяются.

## 7. Критерии готовности к предъявлению

- [ ] Выбраны минимум пять основных статей; их PDF, версии и причины выбора описаны.
- [ ] Библиографии сверены с оригиналами; все записи учтены, попытки обработки сохранены.
- [ ] Есть переиспользуемый скрипт и инструкция запуска; проверен повтор после прерывания.
- [ ] Неоднозначность, отсутствие открытой копии и сетевой сбой различаются в данных.
- [ ] Цитируемые источники для вопросов доступны и проверены по библиографии.
- [ ] Подготовлен согласованный объём вопросов; каждая принятая запись содержит ответ и достаточное доказательство со страницей.
- [ ] Выполнена ручная проверка; черновики и отклонённые вопросы не входят в итоговый набор.
- [ ] Нет дубликатов ID, висячих связей, неизвестных страниц и расхождений хешей.
- [ ] Подготовлены отчёт о данных и зафиксированная версия контрольного набора.
- [ ] Автор воспроизводит запуск, объясняет код и разбирает один удачный и один неудачный случай без опоры на готовый текст ответа.

Обученная модель, сравнение нейронных методов и полный сайт не требуются для этих двух задач. Они появятся после подготовки пригодных для оценки данных.
