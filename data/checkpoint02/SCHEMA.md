# Данные второго чекпойнта

[Задачи и критерии](../../docs/checkpoints/checkpoint-02.md)

Состояние: формы для заполнения. CSV содержат только заголовки; JSONL пусты. Здесь нет реального корпуса или готовой разметки. Формат выбран для пилота и может быть изменён до первой зафиксированной версии.

## Общие правила

- Кодировка UTF-8. CSV использует запятую; текст с запятыми, кавычками и переводами строк записывается через стандартный CSV writer.
- JSONL содержит один JSON-объект на строку, без комментариев и многострочных объектов. Отсутствующее значение — `null`; в CSV — пустое поле. Отсутствие данных не обозначается нулём.
- ID — устойчивые строки: `p001` для пространства, `doc001` для выбранной версии публикации, `ref001` для записи библиографии, `ev001` для доказательства, `q001` для вопроса. Это примеры формы ID, а не существующие записи.
- Один PDF может относиться к нескольким пространствам. ID документа сохраняется; записи библиографии и связи с пространствами остаются отдельными.
- Для пилота одна строка `papers.csv` описывает конкретную выбранную версию PDF. `family_id` объединяет версии одной научной работы. При другой версии PDF создаётся другой `paper_id` и сохраняется семейство.
- SHA-256 записывается 64 шестнадцатеричными символами в нижнем регистре. Дата проверки — ISO 8601 с часовым поясом, например форма `YYYY-MM-DDTHH:MM:SSZ`.
- PDF и полные производные тексты не загружаются в Git. В формах допустимы относительные пути внутри проекта; приватные пути и ключи API не сохраняются.

## parents.csv — основные статьи

| Поле | Смысл |
|---|---|
| `parent_id` | Уникальный ID рабочего пространства |
| `paper_id` | Ссылка на `papers.csv`: основной PDF |
| `topic` | Выбранная тема |
| `selection_reason` | Почему статья включена; отметить влияние доступности источников |

В готовом наборе минимум пять разных основных работ, а не пять файлов одной публикации.

## papers.csv — публикации и файлы

| Поля | Правило |
|---|---|
| `paper_id`, `family_id` | Уникальная версия документа и семейство публикации |
| `title`, `authors`, `year` | Проверенные метаданные; авторы в одном поле, разделённые точкой с запятой |
| `doi`, `arxiv_id`, `version` | Известные идентификаторы; неизвестные поля пусты. Версия arXiv указывается явно, если известна |
| `source_url` | Фактическое происхождение выбранного файла или записи |
| `pdf_path`, `pdf_sha256` | Относительный путь к локальному PDF и его хеш; для недоступного файла пусты |
| `license` | Известная лицензия конкретной версии; `unknown`, если она не установлена |
| `download_status` | `pending`, `downloaded`, `manual`, `no_open_copy`, `failed` |
| `parse_status` | `not_started`, `parsed`, `partial`, `failed` |

`downloaded` означает успешное автоматическое получение и проверку PDF; `manual` — добавление человеком. `no_open_copy` означает, что открытое размещение не найдено среди проверенных источников, а не доказанную недоступность во всём интернете. Ошибка сети получает `failed` и журнал попыток. Перед замораживанием принятые вопросы не должны ссылаться на недоступный PDF.

## references.csv — вся библиография

| Поля | Правило |
|---|---|
| `reference_id` | Уникальная запись; ссылка на одну работу у разных родителей имеет разные IDs |
| `parent_id` | Основная статья из `parents.csv` |
| `reference_index` | Порядковый номер в исходной библиографии, начиная с 1 |
| `raw_reference` | Исходный текст записи, не заменяется исправленными метаданными |
| `matched_paper_id` | Выбранная версия цитируемой работы; пусто при неподтверждённом совпадении |
| `match_method` | `doi`, `arxiv`, `metadata`, `manual` или пусто до сопоставления |
| `match_status` | `pending`, `matched`, `ambiguous`, `not_found`, `error` |
| `notes` | Основание решения, причина неоднозначности, ручное исправление |

Каждая учтённая запись библиографии остаётся в таблице независимо от наличия PDF. `matched` требует существующего `matched_paper_id`. Автоматический поиск по названию считается кандидатом, пока не проверены остальные поля. Несколько кандидатов сохраняются в журнале, а не выбираются произвольно.

## download_attempts.jsonl — журнал обработки ссылок

Несмотря на имя файла, здесь учитывается весь путь к полному тексту, включая неудачу до скачивания.

| Поле | Тип и назначение |
|---|---|
| `event_id` | Уникальная строка |
| `reference_id` | Строка, связь с библиографией |
| `paper_id` | Строка или `null`, если публикация ещё не установлена |
| `stage` | `resolve_metadata`, `find_fulltext`, `download_pdf`, `validate_pdf` |
| `provider` | Источник метаданных или файла |
| `query_or_url` | Запрос или URL без секретов |
| `candidate_ids` | Массив найденных DOI/arXiv ID; пустой, если кандидатов нет |
| `result` | `success`, `no_match`, `ambiguous`, `no_open_copy`, `error`, `cached`, `manual` |
| `http_status` | Целое число или `null`, если HTTP не выполнялся |
| `error_type`, `message` | Строки или `null`; причина и краткое пояснение |
| `attempted_at` | Время попытки |

Для каждой `reference_id` нужна хотя бы одна запись, объясняющая её итоговое состояние. Повторное использование уже полученного PDF отмечается как `cached`. Ручная загрузка имеет `manual` и не учитывается как успех автоматического скачивания. Журнал дополняется, а не перезаписывается только последним успехом.

## evidence.jsonl — проверенные доказательства

| Поле | Тип и назначение |
|---|---|
| `evidence_id` | Уникальная строка |
| `paper_id`, `pdf_sha256` | Документ и точный хеш его PDF |
| `page_number` | Положительное целое; страница PDF с отсчётом от 1 |
| `section` | Название раздела или `null` |
| `quote` | Дословный достаточный фрагмент источника, проверенный по PDF |
| `extraction_version` | Версия способа извлечения; `manual`, если фрагмент введён вручную |
| `page_text_sha256` | Хеш точного извлечённого текста страницы или `null` при ручной привязке |
| `char_start`, `char_end` | Начало включительно и конец исключительно в этом тексте страницы; оба `null`, если надёжной привязки нет |
| `review_status` | `draft`, `approved`, `rejected` |
| `reviewed_by`, `reviewed_at`, `review_notes` | Проверяющий, дата и заметки; неизвестное — `null` |

Для пилота доказательство находится на одной странице и само достаточно для ответа. Многостраничный или составной ответ пока исключается либо откладывается до расширения схемы. При заданных символьных границах обязателен `page_text_sha256`, а полученная подстрока должна совпадать с `quote`. Переносы строк и нормализация обрабатываются версионированно; при сомнении выбирается честная ручная привязка по странице.

Статус `approved` требует проверки человеком, даты и имени/идентификатора проверяющего. Он означает проверку этой разметки, а не независимую экспертизу научного вывода статьи.

## questions.jsonl — вопросы и ответы

| Поле | Тип и назначение |
|---|---|
| `question_id`, `parent_id` | Уникальный вопрос и рабочее пространство |
| `reference_ids` | Непустой массив записей библиографии этого родителя |
| `question`, `answer` | Самостоятельный вопрос и проверенный краткий ответ |
| `evidence_ids` | Непустой массив доказательств; каждое само достаточно для ответа в пилотной схеме |
| `language` | Для основного пилота `en` |
| `question_type` | `method`, `data`, `setup`, `result`, `limitation` |
| `generation_method` | `manual` или `llm_assisted` |
| `generator_model`, `generator_provider`, `prompt_version` | Строки для LLM либо `null` для ручной подготовки |
| `review_status` | `draft`, `approved`, `rejected` |
| `reviewed_by`, `reviewed_at`, `review_notes` | Сведения о ручной проверке |
| `split` | `development_control` для пилота |

Все `reference_ids` должны принадлежать указанному `parent_id`. Каждый документ из `evidence_ids` должен быть подтверждённым источником хотя бы одной из этих записей. Принятый вопрос использует только `approved`-доказательства и доступные PDF. Вопрос, по которому искомый источник не найден, остаётся черновиком или отклоняется с причиной.

Текст ответа может быть переформулирован, но не должен добавлять сведения сверх доказательства. Если доказательства представляют альтернативные достаточные ответы, их варианты необходимо согласовать при проверке; спорная запись не принимается автоматически.

## manifest.template.json — будущая версия набора

Скопировать в `manifest.json` **после** наполнения и проверки. Заменить `template` на `frozen`, заполнить фактические количества и время. `code_commit` указывает на уже существующий коммит проверенного кода сбора/проверки; он не должен ссылаться сам на себя.

В `files` записать объекты с `path` и `sha256` для CSV/JSONL и манифеста PDF. Сам `manifest.json` в собственный список хешей не включается. Версия должна позволять восстановить файлы корпуса из разрешённого DVC-хранилища или повторной загрузки; одних удалённых URL для воспроизводимости недостаточно.

Пустые формы не замораживаются под видом готового набора. `question_count` считает только принятые вопросы; черновики и отклонённые строки учитываются отдельно в отчёте. Поля `unique_question_count` и `evidence_count` помогают заметить повторение одних фактов.

## Проверки перед фиксацией

1. Уникальность IDs и существование всех связей, включая связь доказательства с библиографией нужного родителя.
2. Минимум пять основных работ; отсутствие неразобранных `pending`-состояний без объяснения.
3. Совпадение хешей PDF и разметки, существование страниц и локальных файлов для принятых доказательств.
4. Наличие ручной проверки у всех `approved`-вопросов и доказательств.
5. Отсутствие пустых вопросов, ответов и цитат, а также точных и смысловых дублей.
6. Полнота журнала по библиографии; ошибки и ручные исправления включены в отчёт.
7. Отдельный учёт прав на распространение: локальная пригодность файла для работы не означает готовность его опубликовать.

Проверяющий скрипт предстоит реализовать по этим правилам. Пока схема служит договорённостью о формате, а не заявлением о наличии автоматической валидации.
